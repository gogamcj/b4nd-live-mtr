## 4. 장시간·장애 주입 시나리오 (Phase 14)

| # | 시나리오 | 앱에서 하는 일 | 자동 검증 (🐧 CI) | 밴드 PC에서 할 일 (🪟) |
|---|----------|----------------|--------------------|------------------------|
| 1 | 2시간 30분 세트리스트 반복 재생, 1분마다 기록 | `--soak <분>` 모드: 셋리스트를 처음부터 끝까지 반복, 1분마다 드롭아웃·늦은 콜백·과부하·DSP 최대 부하·MIDI 지연·프로세스 메모리(RSS)·오디오 RAM을 화면 출력, 로그, CSV로 남김. 합격: 드롭아웃 0, 1분 이후 메모리 증가 < 50 MB | 12분, 5곡, RAM 예산 3곡분(곡을 넘길 때마다 디코딩·해제 반복), JACK dummy 8출력. 메모리만 판정 (가상 장치는 실시간이 아니어서 드롭아웃은 기록만). Windows CI는 장치 없이 4분 | 아래 "밴드 PC soak" 명령으로 150분, 실제 곡·VSTi·모듈로. 드롭아웃 0이어야 합격 |
| 2 | 재생 중 USB MIDI 분리 → 재연결 | Phase 4: 1초마다 포트 확인, 재연결 시 프리셋 재전송 | 단위 테스트 (가짜 포트) | 실제 장비로 |
| 3 | 재생 중 오디오 인터페이스 분리 | Phase 2: 즉시 정지, 같은 장치 재연결 | JACK 서버 종료·재시작 | UR22C USB 분리 |
| 4 | 미디어 파일 삭제 후 프로젝트 열기 | 공연 전 점검의 빨간 항목 → LIVE MODE 버튼이 점검 창을 열고 진입하지 않음 (리허설용 "ENTER ANYWAY"는 확인 후 가능, 로그에 남김) | 파일 하나 숨기고 열기 → 거부. 장치 없음 → 거부. 모두 정상 → 진입 | |
| 5 | 백그라운드 CPU 부하 중 재생 | 드롭아웃 카운트·로그 (Phase 2) | 가상 장치 드롭아웃이 로그에 남는 것 확인 | 다른 프로그램을 돌리며 soak |
| 6 | 강제 종료 후 재실행 | 재생 중 10초마다(그리고 재생·정지·곡 선택 때) 위치 기록. 비정상 종료가 감지되면 "멈춘 곳에서 계속?" 제안 | `kill -9` (Windows: Stop-Process -Force) 후 다시 열기 → 3번 곡 15초대로 복귀. 정상 종료 후에는 제안 없음 | 실제로 전원 버튼 |
| 7 | 절전/화면보호기 | Live Mode나 재생 중에는 `SetThreadExecutionState`로 절전·화면 꺼짐 차단, 끝나면 해제 | Windows CI에서 호출 성공 로그 | 노트북 덮개·절전 시간 1분으로 해 두고 확인 |

### 밴드 PC soak (Windows)

```
"B4ND LIVE MTR.exe" --screenshot soak.png --with-audio --project "D:\공연\2026-12.b4nd" --soak 150 --soak-csv soak.csv
```

- `--soak-song-seconds 60`을 붙이면 곡마다 60초만 재생하고 넘어간다 (곡 전환을 많이 시험)
- 결과는 마지막 줄 `soak result: PASS/FAIL`과 `soak.csv`, 로그 폴더(`%APPDATA%\B4ND LIVE MTR\logs`)
- 공연과 같은 버퍼(256 이하), 전원 옵션 고성능, 다른 프로그램 종료 상태로
